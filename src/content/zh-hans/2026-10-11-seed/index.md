这篇文章的用途不是写作，而是**验证**。它是内容流水线的第一个样本：在真正的第一篇文章出现之前，它也是首页、文章列表与标签页唯一的数据来源。

## 它要验证什么

它同时承担两件事：证明 frontmatter 的合同成立，以及让渲染器支持的每一种 GFM 特性都至少出现一次。

| 检查项                           |   负责的一方   | 是否通过 |
| :------------------------------- | :------------: | -------: |
| 文件夹名即 `id`，语言取自文件夹  | 内容集合的定义 |       是 |
| 表格、任务列表、删除线与自动链接 |   GFM 的解析   |       是 |
| 脚注与代码高亮                   | 渲染器的后处理 |       是 |

### 一份清单

- [x] frontmatter 的每个字段都有归属
- [x] 段落、表格与代码块共存
- [ ] 封面图片，留给真正的文章

行内元素同样各有规则：`pnpm build` 这样的命令、~~被推翻的旧说法~~，以及裸写也会成为链接的地址，都需要各自的渲染逻辑，因此它们放在同一段里。自动链接写在这句话的末尾，免得它把后面的文字一并吞掉：https://astro.build

## 脚注与代码块

脚注把补充说明移出正文[^1]；代码块则让语言的语法高亮生效：

```yaml
# 集合的定义只写一次，引用它的地方不重复它。
loader: glob
pattern: "**/*.md"
```

> 引用块把一段话从正文里抬出来，但它本身不带任何语义；要表达「注意」之类的语气，靠的是文字而不是标记。

[^1]: 脚注是 GFM 的扩展之一，与表格、任务列表、删除线和自动链接并列。
